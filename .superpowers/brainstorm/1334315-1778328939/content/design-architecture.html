Two Seeded ECC Agents

Executive Control Agent
role: orchestrator
adapterType: ecc
companyId: null

Represents: JayJay ↔ ECC operator link.
Active during: topic matching + Telegram reply phase.
Client Control Agent
role: orchestrator
adapterType: ecc
companyId: null

Represents: ECC → company topic execution.
Active during: tool calls + company task work.

Auto-seeded once on server startup if missing. IDs stored in env/config or looked up by adapterType=ecc.

Data Flow — Status Lifecycle

Telegram message arrives
  ↓
orchestrator.ts: setAgentProcessing(execAgentId, topicId, topicName)
  ↓ spawn Claude CLI subprocess
orchestrator.ts: setAgentProcessing(clientAgentId, topicId, topicName)
  ↓ ... resolve_conversation + tool calls ...
  ↓ complete_conversation_turn
orchestrator.ts: setAgentIdle(execAgentId) + setAgentIdle(clientAgentId)
    → sets status=idle, lastHeartbeatAt=now, clears metadata
